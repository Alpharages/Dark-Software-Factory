## Bugs

### F1 — Failed login shows NO error; page silently blanks out · **Major**

A user who enters a valid email + wrong password gets **no feedback at all**: no error text, no toast. The login form silently clears and the page reloads. It looks broken / like nothing happened.

**Root cause** — `dsf-dasbhoard/src/api/client.ts:68-89`. The global Axios 401 interceptor treats _every_ 401 as an expired session: it tries a token refresh, finds no refresh token (user is logged out), and calls `redirectToLogin()` which does a **full `window.location.href` navigation**. That hard reload happens before `LoginPage`'s `catch` can render `setErrors({general})` / `toast.error(...)` (`LoginPage.tsx:82-86`) — so the error never appears, and the page-level state is wiped. The `/auth/login` endpoint is not exempted from the session-expiry interceptor.

**Proof (differential):**

- Wrong password → backend returns `401 {"message":"Invalid credentials"}` → **form clears, URL becomes `/login?returnUrl=%2Flogin`, no error shown.**
- Too many attempts → backend returns `429` → error **"Too many login attempts. Try again in 15 minutes." displays correctly and the form is retained.**

  The only difference is the status code: 429 propagates to the page handler; 401 is hijacked by the interceptor. This isolates the cause to the 401 branch.

**Steps to reproduce:**

1. Log out (or open `/login` logged-out).
2. Enter `admin@darksoftwarefactory.com` + any wrong password.
3. Click **Log In**.
4. Observe: form blanks, URL gains `?returnUrl=%2Flogin`, no "Invalid email or password" message or toast.

**Expected:** Inline error + toast "Invalid email or password" (the handler that already exists), form values retained.

**Suggested fix:** In the 401 interceptor, skip the refresh/redirect path when the failing request is an auth endpoint (`/auth/login`, `/auth/refresh`) and let the error reject normally. e.g. guard on `originalRequest.url?.includes('/auth/login')`.

### F2 — Duplicate `/auth/me` requests on every page · **Minor**

Every route load fires **4 identical** `GET /api/v1/auth/me` calls (seen on all 24 pages). Likely multiple independent `useAuth`/auth consumers each fetching, amplified by React StrictMode's double-invoke in dev. Wasteful round-trips; should be a single shared/deduped query (e.g. one TanStack Query key).
_Caveat: part of the 4× is dev-only StrictMode; confirm against a production build before sizing the fix._

### F3 — Typo on Architecture Review Metrics · **Trivial**

`/architecture-review/metrics` empty state reads **"No enough data to…"** → should be **"Not enough data…"**.
