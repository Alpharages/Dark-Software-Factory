## Redesigned Story Outlines

### NEW Story 5.1: PM Dashboard API & Core Orchestration

**Merged From:** Original Stories 5.1 (PM Dashboard Frontend Foundation) + 5.2 (Project List & Status Overview)

**As a PM,**  
I want a unified dashboard with all my projects and their status,  
So that I can monitor my portfolio at-a-glance and take quick actions.

**Delegation Strategy:**
- **DSF BUILDS:** 
  - REST API endpoints (`GET /api/v1/pm-dashboard/projects`, `/api/v1/pm-dashboard/summary`)
  - Socket.IO gateway setup for real-time updates
  - Database queries with Prisma (project aggregations, ticket counts)
  - Authentication guards (@JwtAuthGuard, @RolesGuard)
  - Pagination logic for large project lists

- **AI DELEGATES:**
  - React dashboard UI components (header, sidebar, project cards)
  - Tailwind CSS styling and responsive layouts
  - Filter/sort/search UI implementation
  - Status indicators (green/yellow/red badges)
  - Empty state handling

**Acceptance Criteria:**
1. **AC#1:** API returns all projects for authenticated PM with ticket counts (total, in-progress, completed, blocked)
2. **AC#2:** Dashboard loads within 2 seconds (NFR-P2) with responsive design (NFR-UX1)
3. **AC#3:** Projects can be filtered (status, client, date), sorted (activity, count, alpha), and searched (name, client)
4. **AC#4:** Real-time updates via Socket.IO when project status changes
5. **AC#5:** UI generated by AI meets WCAG 2.1 AA accessibility standards (manual review required)

**Estimated Effort:** 3 days (2 days API + 1 day AI integration and review)  
**Dependencies:** Story 1.6 (Auth), Epic 2 (Data to display)  
**FRs Covered:** FR8, FR96, FR97

3. **AC#3:** Progress indicators show current step, estimated time (if available), AI provider icon

### NEW Story 5.3: Code Approval & Quality Gate Workflows

**Merged From:** Original Stories 5.4 (Code Approval Workflow Interface) + 5.5 (AI Confidence Scores & Uncertainty Flags)

**As a PM,**  
I want to review AI-generated code with QA results and confidence scores before deployment,  
So that I maintain control over production quality.

**Delegation Strategy:**
- **DSF BUILDS:**
  - Approval state machine (business logic for approve/reject/rework/escalate)
  - API endpoints:
    - `POST /api/v1/executions/{id}/approve`
    - `POST /api/v1/executions/{id}/reject` (with feedback)
    - `POST /api/v1/executions/{id}/rework` (with clarifications)
    - `POST /api/v1/executions/{id}/escalate` (to TL)
  - Database persistence (approval decisions, audit trail)
  - RabbitMQ queue publishes (trigger GitHub push on approval)
  - Auto-escalation logic (if confidence < 70% → escalate to TL)

- **AI DELEGATES:**
  - Code diff viewer UI (integrate `diff2html` or `react-diff-viewer`)
  - QA results summary display (tables, badges, charts showing lint/test/coverage)
  - Confidence score visualization (0-100% gauge, color-coded)
  - Uncertainty flags UI (expandable list of AI concerns)
  - Approval action forms with validation

**Acceptance Criteria:**
1. **AC#1:** PMs can view code diff with syntax highlighting and line numbers
2. **AC#2:** QA summary displays lint status, test pass/fail counts, coverage %, security scan results
3. **AC#3:** Confidence score prominently displayed (90-100% green, 70-89% yellow, <70% red)
4. **AC#4:** Low confidence (\u003c70%) automatically escalates to TL and requires PM approval (cannot auto-deploy)
5. **AC#5:** Approval decision logged to audit trail with timestamp, PM ID, reasoning
6. **AC#6:** Original ticket and acceptance criteria displayed side-by-side with code for context

**Estimated Effort:** 3.5 days (3 days backend workflow + 0.5 day AI-generated UI)  
**Dependencies:** Epic 3 (QA results), Epic 4 (Code ready), Epic 2 (Confidence scores from Story 2.3)  
**FRs Covered:** FR11, FR12, FR13, FR14

### NEW Story 5.4: Workload Management & Capacity Planning

**Merged From:** Original Stories 5.6 (Workload & Capacity Dashboard) + 5.7 (Manager View - Team Capacity Overview)

**As a PM,**  
I want to monitor my workload and capacity,  
So that I can prevent burnout and request help before overload.

**As a Manager,**  
I want to see all PMs' workload distribution,  
So that I can balance capacity and prevent team burnout.

**Delegation Strategy:**
- **DSF BUILDS:**
  - Utilization calculation API:
    - PM view: `GET /api/v1/workload/pm/{id}`
    - Manager view: `GET /api/v1/workload/team` (RBAC @Roles('MANAGER'))
  - Database aggregations (count active tickets, calculate utilization %)
  - Burnout risk calculation (0-60% green, 61-80% yellow, 81-100% red)
  - Alert logic (>80% utilization → notify PM and Manager)
  - Project reassignment: `POST /api/v1/projects/{id}/reassign` (Manager only)
  - Prometheus metrics (`pm_utilization_percent` gauge)

- **AI DELEGATES:**
  - Utilization dashboard UI (gauges, bar charts, trend graphs)
  - Burnout risk indicators (color-coded alerts)
  - Workload metrics visualization (tickets created/approved/rejected, revision rate)
  - Manager team capacity view (bar chart of all PMs' utilization)
  - Drag-and-drop project reassignment UI (integrate `react-beautiful-dnd`)

**Acceptance Criteria:**
1. **AC#1:** PMs see current utilization % (active_tickets / max_tickets * 100)
2. **AC#2:** Burnout risk indicator displays (green/yellow/red) with threshold explanations
3. **AC#3:** Alerts trigger when PM >80% utilization (notify PM, Manager, and leadership)
4. **AC#4:** Managers see all PMs' utilization in sortable bar chart
5. **AC#5:** Managers can reassign projects via drag-and-drop (updates `projects.pm_id`)
6. **AC#6:** Capacity trends over time displayed (weekly chart showing historical utilization)

**Estimated Effort:** 3.5 days (2.5 days API + metrics + alerts + 1 day AI-generated charts/UI)  
**Dependencies:** Epic 2 (Ticket data)  
**FRs Covered:** FR15, FR16, FR17, FR18, FR19

### NEW Story 5.5: Client Communication Intelligence (AI-Heavy)

**Formerly:** Original Story 5.8 (Client Communication Log)

**As a PM,**  
I want to log client conversations with AI transcription and analysis,  
So that I have searchable history with automatic action items and sentiment tracking.

**Delegation Strategy:**
- **DSF BUILDS:**
  - Conversation storage (new table: `client_conversations`)
  - API endpoints:
    - `POST /api/v1/conversations` (create conversation record)
    - `POST /api/v1/conversations/{id}/link-project`
    - `GET /api/v1/conversations?projectId={}&clientId={}`
  - File upload handling (meeting transcripts, audio files)
  - Database relations (link conversations to projects/tickets)
  - Search indexing (ElasticSearch or PostgreSQL full-text search)

- **AI DELEGATES:**
  - **Transcription:** Audio/video → text (Whisper API, Rev, Otter.ai)
  - **Summarization:** Meeting transcript → key points summary (GPT-4)
  - **Action Item Extraction:** Transcript → list of action items with owners (GPT-4)
  - **Sentiment Analysis:** Client tone → satisfaction score (positive/neutral/negative)
  - **Auto-Ticket Creation:** Action items → draft tickets for PM approval
  - **Conversation UI:** Upload form, transcript viewer, summary display

**Acceptance Criteria:**
1. **AC#1:** PMs can upload meeting audio/transcript and link to project
2. **AC#2:** AI generates summary of key points within 30 seconds
3. **AC#3:** AI extracts action items with suggested owners and due dates
4. **AC#4:** Sentiment analysis shows client satisfaction level (happy/neutral/concerned)
5. **AC#5:** Auto-generated tickets from action items require PM approval before creation
6. **AC#6:** Conversations are searchable by keyword, client, date, project, sentiment

**Estimated Effort:** 2.5 days (2 days storage + API + search + 0.5 day AI integration)  
**Dependencies:** Epic 2 (Context extraction patterns)  
**FRs Covered:** FR20, FR23  
**Token Cost:** Estimate $0.50-$2.00 per meeting (acceptable vs. manual summarization time)

### NEW Story 5.6: Reporting & Analytics Generation (AI-Heavy)

**Formerly:** Original Story 5.9 (Sprint Review & Progress Reporting)

**As a PM,**  
I want to generate progress reports for client sprint reviews,  
So that I can share transparent updates efficiently without manual report writing.

**Delegation Strategy:**
- **DSF BUILDS:**
  - Data aggregation API:
    - `GET /api/v1/reports/sprint?projectId={}&startDate={}&endDate={}`
    - Fetch tickets, executions, QA results from database
    - Calculate velocity (tickets completed vs. planned)
    - Aggregate quality metrics (test pass rate, coverage %, defects)
  - Report template storage (configurable per client)
  - Caching layer (don't regenerate same report twice)

- **AI DELEGATES:**
  - **Report Content Generation:** Data → narrative sprint summary (GPT-4)
  - **Chart Creation:** Velocity trends, quality metrics charts (Chart.js/Recharts)
  - **Insights Extraction:** Data → recommendations and observations
  - **PDF Export:** HTML report → PDF (Puppeteer)
  - **PowerPoint Export:** Data → .pptx slides (pptxgenjs library)
  - **Report UI:** Template selection, date range picker, export options

**Acceptance Criteria:**
1. **AC#1:** Report includes sprint summary, ticket breakdown, velocity metrics, quality metrics, upcoming sprint plan
2. **AC#2:** Reports generated in <5 seconds (with caching)
3. **AC#3:** Export formats available: PDF download, web view (shareable link), PowerPoint
4. **AC#4:** Reports are cached (same sprint + date range → return cached version)
5. **AC#5:** AI-generated narrative is accurate and matches data (manual spot-check required)
6. **AC#6:** Charts are visually appealing and correctly represent data

**Estimated Effort:** 1.75 days (1.5 days data aggregation + API + caching + 0.25 day AI integration)  
**Dependencies:** Epic 3 (QA metrics), Epic 2 (Ticket data)  
**FRs Covered:** FR21, FR22  
**Token Cost:** Estimate $0.20-$1.00 per report (mitigated by caching)
