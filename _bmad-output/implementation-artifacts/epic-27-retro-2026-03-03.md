### 3.2 What Went Well (Successes & Strengths)

- **Code review consistency:** Every story had structured AI/SM code review. Reviews caught layout regressions (27-3 md breakpoint, double TooltipProvider), auth guard bypass via `...options` spread (27-7), refetchInterval violating AC (27-4), and accessibility/UX gaps (aria-labels, error states). Fixes were applied before marking stories done.
- **Shared navigation config:** Story 27-3 extracted navigation to `src/config/navigation.ts` and 27-5 migrated to `ImprovedSidebar` using the same config, reducing drift between mobile drawer and desktop sidebar.
- **Auth and query discipline:** Story 27-7 applied `enabled: !!user` across 8+ hooks (approvals, notifications, executions, QA review, system config), eliminating premature API calls from components that render outside `ProtectedRoute` (e.g. `NotificationCenter` in Header).
- **Reuse over reinvention:** 27-4 relied on existing NotificationCenter badge and React Query; 27-6 reused `DockerService.isHealthy()` and `ConfigService` for integration health. No duplicate implementations.
- **Test coverage:** New or expanded tests for NotFoundPage/App route, useDocumentTitle, Sidebar/ImprovedSidebar, NotificationCenter (badge, aria, error state), Integration Health (backend AppService), AppContent/ProtectedRoute and useApprovals auth guards improved confidence and regression safety.

### 3.3 Challenges & Growth Areas

- **Layout and breakpoint coupling:** 27-3 and 27-5 had to align `md`/`lg` breakpoints and sidebar width/margin across `App.tsx`, `Sidebar`, and `ImprovedSidebar`. Initial oversights (redundant width classes, nested `TooltipProvider`) caused review rework.
- **Hook option spread order:** 27-7 revealed that `enabled: !!user` must come after `...options` in several hooks so callers cannot override the auth guard. This pattern should be documented for future hooks.
- **Story file location:** Epic 26 retro committed to standardizing story file location (e.g. `implementation-artifacts/stories/`). Epic 27 story files remained in `implementation-artifacts/` (root). Single folder achieved; “stories” subfolder not adopted.

### 3.4 Key Insights

- **Code review during development continued to pay off:** The habit from Epics 25 and 26 was sustained. HIGH/MEDIUM fixes (breakpoints, auth guards, refetchInterval, aria, error states) were caught in-story and fixed before done.
- **Layout is a system:** Mobile drawer, tablet icon sidebar, and desktop expanded sidebar share one navigation source of truth. Changing one (e.g. 27-5 migrating to ImprovedSidebar) required care so mobile/tablet behavior stayed correct.
- **Auth gates are critical for layout-mounted hooks:** Header and DashboardLayout render outside ProtectedRoute, so any hook used there (notifications, approvals, etc.) must use `enabled: !!user` to avoid 401s during cold load or redirect.
