## 3. Challenges & Lessons Learned

**Bob (Scrum Master):** "What were the friction points?"

**Charlie (Senior Dev):** "**Native bindings** are always a risk. Installing `node-pty` required build tools on the host. We need to ensure the Docker environment handles this correctly for production."

**Elena (Junior Dev):** "**Mocking PTY streams** in tests was tricky. We had to ensure the mocks correctly simulated the chunked output to verify the real-time logging logic (Story 19.2)."

**Dana (QA Engineer):** "We identified a **missing module** (Story 19.5). `AIDecisionLoggerService` was referenced but not yet implemented, so we had to use temporary local logging for project deletions. It's a small gap but one that needs filling."

**Lessons Learned:**

1.  **TTY is Essential:** For advanced AI CLIs (Claude, Cursor), a real PTY is vastly superior to standard `exec` for capturing progress and handling interactions.
2.  **Persistence Strategy:** Mapping workspaces to `ticketId` rather than `executionId` is the correct approach for multi-step agent tasks.
3.  **Real-time Observability:** Users (and developers) need to see the "thought process" of the agent in real-time, not just the final result.
