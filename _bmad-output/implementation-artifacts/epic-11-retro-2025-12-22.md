## 4. Key Insights & Patterns Discovered

**Bob (Scrum Master):** "Let's extract the learnings. What patterns or insights emerged from this epic?"

### 💡 Pattern 1: Gradual API Evolution

**Charlie (Senior Dev):** "We saw **service APIs evolve intelligently** across stories. Story 11.2 built `logDecision()`, then Story 11.5 added three query methods (`getDecisionTimeline`, `getLowConfidenceDecisions`, `searchDecisions`) to the same service. This is the right way to grow an API."

**Anti-pattern Avoided:** Creating a new service for queries instead of extending the existing one

### 💡 Pattern 2: Index-Driven Performance

**Dana (QA Engineer):** "Story 11.5 showed **proactive performance optimization**. They added `@@index([confidence, timestamp])` BEFORE implementing low-confidence queries because they knew it would be needed. That's good architecture."

**Evidence:** Migration `20251222053611_add_confidence_index` created for Story 11.5

### 💡 Pattern 3: Graceful Degradation

**Elena (Junior Dev):** "The **error handling philosophy** across all stories is really smart. Services return `null` or `[]` on failures instead of crashing. Metrics and Sentry calls are fire-and-forget. The system keeps running even when non-critical stuff fails."

**Code Pattern from Story 11.2:**

```typescript
} catch (error) {
  this.logger.error('Failed to create audit log', { error, ticketId });
  this.sentry.captureException(error);
  return null; // Graceful degradation - don't crash calling service
}
```

### 💡 Pattern 4: Strategic Work Deferral

**Alice (Product Owner):** "This epic had **smart scope management**. Multiple stories deferred complex work (E2E tests, GitHubPROrchestrator, service unit tests) with clear action items instead of blocking delivery. That's disciplined execution."

**But:** This creates technical debt we need to track
