## 3. Epic Review

### 3.1 What Went Well (Successes & Strengths)

- **Backend Health:** Eliminated all ERROR and WARN logs on boot natively by cleaning out deprecated modules and fixing routing configurations (`ActionableStatusService` removal, path-to-regexp v8 compliance).
- **Socket and API Efficiency:** Significant win in Story 25.6 by centralizing `Socket.IO` context. `staleTime` overrides effectively slashed duplicate React Query API background requests, significantly improving the real-time application feel without violating rate limits.
- **Frontend Layouts:** Recharts layout shifts and zero-dimension mount errors were successfully mitigated across the Observability and Financial metric pages using Tailwind's `min-w-0` correctly and matching `ResponsiveContainer` skeleton heights.

### 3.2 Challenges & Growth Areas

- **Testing Blindspots:** A recurring theme was identified regarding frontend test coverage. Code reviews repeatedly caught uncaught TypeError crashes because backend data contracts did not 1-to-1 match the UI assumptions, bringing down the entire view implicitly.
- **AI Code Review Timing:** It was raised that doing AI Code Reviews _at the end_ of the story caused significant friction and rework during the PR phase, when basic edge cases could have been resolved during the active implementation.

### 3.3 Key Insights

- TypeScript typing provides structural static checks but relies on the actual data fetch. A missing API field or a mismatched payload instantly bypasses TypeScript compiling. Robust frontend tests using DOM verification (e.g. React Testing Library) are required to guard against these implicit data assumptions.
- By shifting Left, performing AI Code edge-case testing earlier into the active development process prevents bugs escaping to the final review cycle.
