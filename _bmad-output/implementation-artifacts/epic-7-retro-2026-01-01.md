# Epic 7 Retrospective: Architecture Review Workflows

**Date:** 2026-01-01  
**Project:** Dark Software Factory  
**Facilitator:** Bob (Scrum Master)  
**Participants:** Khakanali (Project Lead), Alice (PO), Team  

## 1. Epic Overview & Context
Epic 7 successfully delivered the "Heart" of the architecture review system. We transitioned from opaque AI autonomous coding to a transparent, risk-based review workflow.

- **Total Stories:** 14/14 Completed (100% Efficiency)
- **Key Deliverables:** ADR Generation, TL Review Queue, AI Escalation, Capability Tracking, and Constraints Management.

## 2. What Went Well (Successes)
- **Transparency**: ADRs are now automatically generated, providing a permanent record of 'Why' decisions were made.
- **Fail-Closed Safety**: Applied the lesson from Epic 6, ensuring the system escalates (blocks execution) when AI uncertainty is high.
- **Metrics Dashboard**: Story 7-8-UI provides real-time visibility into architecture health.
- **Rapid Remediation**: Most stories passed adversarial review with only minor fixes required.

## 3. Challenges & Critical Discoveries
- **The "Visibility Gap"**: We discovered a systemic neglect of UI-first planning. Backend components were often build 'dark', leaving the Project Lead directionless on how to interact with the new features.
- **Complexity of Mocks**: Heavy reliance on Prisma mocks in tests caused friction during integration.
- **Technical Debt**: AC#5 (Filtering) for constraint management was deferred; React 19/Vitest environment issues persist in CI for some UI components.

## 4. Key Insights & Lessons Learned
- **UI is a First-Class Citizen**: Autonomous backends are useless without control panels. We must bundle UI stories with backend features.
- **"Proactive Audit" Pattern**: Instead of waiting for the user to ask, the team should preemptively identify missing interaction points.
- **Escalation is Empowerment**: Users feel safer when they know the AI *will* stop and ask for help.
