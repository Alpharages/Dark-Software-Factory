## Challenges

### ⚠️ Configuration Key Mismatch (23-1)

**Issue:** Code review discovered `gitMirror.enabled` config key mismatch.

**Impact:** HIGH - Would have broken mirror feature in production.

**Root Cause:** Inconsistent naming between env.validation.ts and workspace.service.ts.

**Resolution:** Fixed to use `ENABLE_GIT_MIRRORING` consistently.

**Lesson:** Configuration key audits should be part of code review checklist.

### ⚠️ Missing Container Assignment Integration (23-2)

**Issue:** Initial implementation missed `assignContainer()` call in pty-execution.service.ts.

**Impact:** MEDIUM - Container IDs weren't being stored, cleanup would fail.

**Root Cause:** Integration point between stories not explicitly documented.

**Resolution:** Added assignContainer() call after container creation in post-review fixes.

**Lesson:** Cross-service integration points need explicit verification in acceptance criteria.

### ⚠️ Test Mock Proliferation

**Issue:** Adding new dependencies required updating 5+ test files with mocks.

**Impact:** MEDIUM - Time consuming, error-prone.

**Root Cause:** No centralized test fixture factory.

**Files Affected:**

- execution-tracker.service.spec.ts
- execution.service.spec.ts
- ai-execution.publisher.spec.ts
- retry-handler.service.spec.ts
- execution.repository.spec.ts

**Lesson:** Consider creating shared test fixtures for common mock patterns.

### ⚠️ Optional Prisma Schema Task (23-1)

**Issue:** Task 6 (Prisma schema for GitMirror tracking) remains optional/unimplemented.

**Impact:** LOW - Metadata JSON file approach works fine.

**Decision:** Keep as JSON-based metadata for simplicity, revisit if scale requires database persistence.
