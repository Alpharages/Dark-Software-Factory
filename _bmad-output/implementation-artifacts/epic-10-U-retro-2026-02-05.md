# Epic 10-U Retrospective: Real-time Notifications & Controls

**Date:** 2026-02-05
**Project:** Dark Software Factory
**Facilitator:** Scrum Master
**Reviewer:** Antigravity (AI Assistant)

## 1. Epic Overview & Context

Epic 10-U focused on implementing the real-time infrastructure required for a responsive "Mission Control" experience. After moving backend observability APIs to Epic 14, this epic concentrated on the "hot path" of execution streaming and user control.

- **Total Stories:** 8 (7 Completed, 1 Cancelled)
- **Key Deliverables:** Socket.IO Infrastructure, Execution Progress Streaming, Manual Intervention Circuit Breaker, Real-time Notification Channels, and the Lead QA Review Dashboard (UI).

## 2. What Went Well (Successes)

- **Execution Progress Streaming (Story 10-U-2):** Successfully implemented robust WebSocket streaming for the entire execution lifecycle context. The decision to use a dedicated stream rather than polling proved critical for the "Real-Time" feel.
- **Circuit Breaker Pattern (Story 10-U-5):** The Manual Intervention Service with its SIGSTOP/SIGCONT Docker integration is a standout win. It provides true human-in-the-loop safety, allowing PMs to pause AI agents instantly—a key trust-building feature.
- **Unified Notification Channels (Story 10-U-7 & 10-U-3):** Integrating QA failure notifications directly into the immediate feedback loop (via `QaNotificationService`) drastically reduces the time-to-awareness for broken builds.

## 3. Challenges & Critical Discoveries

- **Socket.IO Security Granularity (Story 10-U-1):** Initial implementation focused on connection-level security. Code review highlighted the valid need for method-level guards (`@UseGuards(WsAuthGuard)`), revealing that "connection auth" !== "operation auth" in WebSocket architectures.
- **Event Flood Management (Stories 10-U-2 & 10-U-4):** Streaming execution logs creates massive event volume. We had to implement adaptive rate limiting and debouncing (500ms) to prevent overwhelming the frontend—a classic real-time distributed system challenge.
- **Frontend-Backend Velocity Mismatch:** The UI implementation (Story 10-UI) had to defer advanced features like "virtual scrolling" for logs. This indicates that while the backend stream is ready, the frontend consumption layer requires more complex state management than standard REST data handling.

## 4. Key Insights & Lessons Learned

- **Event Hygiene is Mandatory:** Real-time features must include throttling and debouncing _by default_, not as an afterthought. "Stream everything" is not a valid strategy without rate limits.
- **WebSocket Auth ≠ HTTP Auth:** Protecting the connection handshake is insufficient. Granular, message-level guards are required for secure operations (e.g., pausing an agent execution).
- **"Circuit Breakers" Build Trust:** Giving users a "Stop" button (manual intervention) psychologically enables them to trust the autonomous system more, knowing they have ultimate control.

## 5. Impact on Future Epics (Epic 14 Preview)

Epic 14 (Observability) will heavily rely on the patterns established here.

- **Strategy:** Apply the "Event Hygiene" lesson to the Observability APIs in Epic 14. Ensure all new metrics endpoints have built-in rate limiting and data aggregation to prevent dashboard overload.

## 6. Action Items

- [ ] **Standardize Debouncing:** Create a shared utility/decorator for debouncing socket events to ensure consistency across the platform.
- [ ] **Frontend Log Virtualization:** Prioritize the "Virtual Scrolling" tech debt in the backlog to allow the UI to handle long-running execution logs smoothly.
- [ ] **WebSocket Security Checklist:** Add "Message-Level Guard Verification" to the DoD for any future real-time stories.
